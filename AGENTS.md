# AGENTS.md

ninty-code: all-Swift macOS AI coding assistant. UI in the app target, ALL agent logic in `Packages/NintyCore`.

## Build & Test

```sh
# Core tests (must pass)
swift test --package-path Packages/NintyCore

# Regenerate Xcode project (required after adding/removing files or targets)
xcodegen generate

# App build (must pass)
xcodebuild -scheme NintyCode -destination 'platform=macOS,arch=arm64' -configuration Debug build CODE_SIGNING_ALLOWED=NO
```

Both must pass before work is considered done.

## Xcode Project

- `NintyCode.xcodeproj` is GENERATED by XcodeGen from `project.yml`. Never edit the `.xcodeproj` directly — edit `project.yml` and run `xcodegen generate`.
- macOS 26+ only, `ARCHS=arm64` only. Bundle ID `ai.ninty.code`.

## Architecture Rules

- `NintyCore` must NEVER import SwiftUI/AppKit/UIKit. Foundation + Network only.
- App target contains zero agent logic — no provider calls, no tool execution, no permission logic.
- UI ↔ core communication only via async streams and types exported by NintyCore.
- Providers: single `OpenAICompatibleProvider` implementation + presets. Do not add per-vendor providers without explicit request.
- Markdown: manual fence-segmentation in `MarkdownText` (no swift-markdown dep). Keep it that way unless a dep is justified.

## Workspaces (multi-root)

- Projects are `Workspace`s (VS Code style): `id`, `name`, `folders[]` — folders[0] = primary root (bash cwd, config source, default for relative paths). Persisted at `~/.config/ninty/workspaces.json` via `WorkspaceStore`.
- `ToolContext` takes `projectRoots: [URL]`. Path rules: absolute passes through; `folderName/relative` addresses the root with that folder name; plain relative resolves against primary. `isInsideProject` = inside ANY root. `mentionPath(for:)` = root-relative, folder-prefixed only when multi-root.
- Sessions are keyed by workspace id (`SessionStore(storageKey:)`). Migrated legacy projects use the old path-hash as workspace id, so `SessionStore(projectRoot:)` and the migrated workspace share a directory — never break this.
- Config: merged from primary root; `AGENTS.md` instructions concatenated from every root (`ConfigLoader.load(roots:)`).

## Code Style

- Swift 6 language mode, strict concurrency. Actors for all mutable shared state.
- `Sendable` on all DTOs crossing isolation boundaries.
- `AsyncThrowingStream` for streaming; no Combine, no completion handlers in new code.
- `@Observable` (Observation framework) in app target; no `ObservableObject`.
- Errors: typed `enum` errors per module. No stringly-typed errors.
- Minimal diffs. No new SPM dependencies without stated justification.

## Secrets

- `auth.json`, `.env`, certificates, API keys: never committed.
- Key flow: env vars (dev), `~/.config/ninty/auth.json` chmod 600 (runtime, written by app), GitHub secrets (CI).

## Git Discipline

- No commits, pushes, or branch mutations unless explicitly requested.
- Commits follow Conventional Commits: `type(scope): subject`.
  - Types: `feat`, `fix`, `docs`, `style`, `refactor`, `perf`, `test`, `build`, `ci`, `chore`, `revert`.
  - Scope: module affected (`core`, `providers`, `tools`, `mcp`, `app`, `ci`, ...). Omit when repo-wide.
  - Subject: imperative, lowercase, no trailing period. Example: `feat(tools): add grep include filter`.
